Overview

Lembrent is a system for naming and drawing base‑60 (Lembrent‑60) and base‑64 (Lembrent‑64) numbers. The scheme is designed so that the value of any digit can be computed directly from the consonants present in its spoken name, making it simultaneously human-pronounceable and algorithmically unambiguous.

The word "lembrent" itself encodes the entire scheme: its six consonants each carry a unique, fixed bit value, and its two vowels (e) serve purely as phonetic scaffolding.

Lembrent‑60 uses digits 0–59; Lembrent‑64 extends the same system to digits 0–63, adding four further values. Both share an identical naming and glyph construction rule.

The word lembrent as it encodes the scheme:

The value of a digit is the sum of the bit values of all consonants present in its name. These six bits span values 0–63, naturally supporting bases up to 64.

The Lembrent Naming Scheme

Digit Structure

Every digit follows a strict template derived from the word lembrent. The two vowels are fixed positional markers; each consonant is either included (its bit is set) or omitted (its bit is clear). Consonants always appear in the fixed order l, m, b, r, n, t.

Example: emrent has value 2⁴ + 2² + 2¹ + 2⁰ = 16 + 4 + 2 + 1 = 23. It contains m, r, n, and t, but not l or b.
Zero: A digit with value zero is written ee — the two vowels with no consonants present.

Multi-Digit Numbers: Length Digits and Significant Digits

A full Lembrent number name is composed of two parts:

  1. A length digit — a single Lembrent digit, prefixed with a base indicator, encoding how many significant digits follow.
  2. The significant digits — the actual base-60 or base-64 digits of the number, each prefixed with a hyphen (-).

The base indicator prefix is s for base‑60 and k for base‑64.

<base-prefix><length-digit>-<digit₁>-<digit₂>-…-<digitₙ>
where digit₁ is the most significant and digitₙ is the units digit

Single-digit numbers: For numbers below 64 (a single significant digit), the length digit is optional. Such a number may be written in full multi-digit form or as a bare digit name.

Zero number: The number zero may be written in any of the following ways:
– `see` (Lembrent-60: a zero length digit with no significant digits)
– `kee` (Lembrent-64: a zero length digit with no significant digits)
– `ee` (bare zero digit, base-agnostic)

Step-by-Step Worked Example — 70 in Lembrent‑60

1
Convert to base‑60. 70 ÷ 60 = 1 remainder 10. So the digits are 1 (60¹ place) and 10 (60⁰ place).
2
Name each significant digit. Digit 1 = eet (bit 0 only → 2⁰ = 1). Digit 10 = eben (bits 3 and 1 → 2³ + 2¹ = 8 + 2 = 10).
3
Determine the length digit. Two significant digits → length value = 2 → een (bit 1 → 2¹ = 2).
4
Assemble. Base‑60 prefix s + length digit een + -eet + -eben = seen-eet-eben.

Glyphs

Each Lembrent glyph consists of a stem stroke plus zero to six arm strokes. The arms are encoded as a 6-bit bitmap — the same bitmap used in the digit's spoken name — so the glyph and name are two representations of the same underlying data structure.

Coordinate Frame

The canvas runs from (−0.5, −0.5) to (0.5, 0.5). The stem tip sits at (0, 0); the canonical arm (before rotation) extends toward (0.5, 0).

Bit 0 is the rightmost arm stroke and bit 5 is the leftmost, so the glyph arm order aligns with the letter order in Lembrent names.

Arm Placements

Placement tokens: 180+, 180-, 90+, 90-, 0+, 0-.

Scheme‑60 forbids digits 60–63 (invalid in base‑60).

SVG Output

Generated SVG files use exact cubic Bézier path data and reuse repeated arm-stroke geometry, so they are minimal and do not rasterise the glyph.

The glyphs toolkit is built on NumPy and Matplotlib (Python 3.10+).

Pronunciation

Each letter has a single, consistent pronunciation regardless of its position. The sole exception is the vowel e, which changes between its doubled form (ee) and its single form (e).

Syllable Structure

If at least one consonant is present between the two es (m, b, or r), there is a syllable break between the vowels — immediately after m, or after the initial e if no m is present. Otherwise the digit is monosyllabic.

Clarity, Tolerance, and Consonant Clusters

Clarity: Because every consonant is semantically significant and the scheme contains no phonetic redundancy, every consonant must be clearly and distinctly enunciated. Speakers who habitually soften or drop final consonants — in particular, final t — must take especial care.
Consonant clusters: Speakers who find clusters such as br difficult may insert a schwa (/ə/) to separate them; the syllable bearing the schwa is unstressed. For example, lembrent may be pronounced as /lɛm brɛnt/ or as /'lɛm bə 'rɛnt/.
Vowel and consonant tolerance: Because vowels carry no semantic weight, slight variation is tolerated. The fixed positional ordering of consonants also makes the scheme resistant to certain mispronunciations: a speaker who renders r as /l/ or t as /d/ can still be understood from the consonant's position alone.

Interactive Calculator

Enter any non-negative integer or arithmetic expression to see its representation in both Lembrent‑60 and Lembrent‑64. The glyphs and Lembrent names are returned live from the API.

Arithmetic operators +, −, *, /, and parentheses are supported. Only non-negative integer results are displayed.

REST API

The Lembrent + Glyphs API is a small FastAPI application that exposes a single endpoint, returning the Lembrent name and per-digit SVG glyphs for any non-negative integer in either base.

GET /lembrent/{radix}/{number}

Query parameters (defaults):
name=1 include the Lembrent name string
svg=1 include per-digit SVG strings
png=0 include per-digit PNGs as base64

Example Requests

curl -s "http://127.0.0.1:8000/lembrent/60/70?name=1&svg=1&png=0"
curl -s "http://127.0.0.1:8000/lembrent/64/12?name=1&svg=1&png=1" | jq .

Caching

The API maintains an in-memory LRU cache (configurable via MAX_CACHE_ENTRIES) and optionally a disk cache stored under api/cache/{cache_version} (configurable via DISK_CACHE_DIR).

Installation

    

      

        
lembrent (Perl CLI)

        

          The lembrent command-line utility converts non-negative
          integers to their Lembrent‑60 or Lembrent‑64 spoken names.
          It requires only Perl 5 — no non-core modules.
        

        
gh=https://github.com
org=Warwick-Allen
git clone $gh/$org/base60.git
cd base60/lembrent
chmod +x lembrent
./lembrent 60 70
# seen-eet-eben

        
To place it on your PATH:

        
sudo cp lembrent /usr/local/bin/lembrent


        
Synopsis

        
lembrent BASE [NUMBER...]

        

          BASE must be 60 or 64.
          Shell arithmetic expressions are accepted as
          NUMBER arguments.
        

      

      

        
glyphs (Python toolkit)

        

          The glyphs toolkit renders Lembrent glyphs as SVG or
          PNG.  It requires Python 3.10+ and uses NumPy and Matplotlib.
        

        
cd base60
python -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"

        
CLI usage

        
# SVG output (digit 12, scheme 60)
glyphs --scheme 60 --digit 12 \
       --svg twelve.svg

# PNG output
glyphs --scheme 60 --digit 12 \
       --png twelve.png

# Manual arm placement
glyphs --scheme 60 \
       --placement 90+ \
       --placement 90- \
       --png m.png

# Write SVG to stdout
glyphs --scheme 60 --digit 12 \
       --svg -

        
Python API

        
from glyphs import (
    Scheme,
    glyph_for_digit,
    plot_glyph,
)
glyph = glyph_for_digit(Scheme.S60, 12)
plot_glyph(glyph)


        
API server

        
pip install -r api/requirements.txt
uvicorn api.app:app --reload --port 8000
